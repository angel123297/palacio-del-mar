## 2. 🪲 Anomalías Detectadas y Remediadas de Inmediato

### 2.1. Bug de Desalineación en Puerto de Base de Datos (MongoDB)
* **Severidad:** Media / Crítica para desarrolladores en entorno local.
* **Diagnóstico:** En `.env.example`, `.env` y `docker-compose.yml`, el mapeo de puerto para MongoDB fue modificado recientemente a `MONGO_PORT=27018`. Sin embargo, en [`application.properties`](file:///C:/Users/hdari/Desktop/palacio-del-mar/backend-java/src/main/resources/application.properties#L6-L7), la URI de conexión de Spring Boot tenía el puerto `27017` hardcodeado de forma estática:
  ```properties
  # Configuración previa defectuosa
  spring.data.mongodb.uri=mongodb://${MONGO_HOST:localhost}:27017/palacio_db
  ```
  Esto provocaba que cualquier intento de ejecutar el backend en la máquina host contra una base de datos levantada en Docker en el puerto 27018 fallara inmediatamente por `MongoSocketOpenException`.
* **Solución Aplicada:** Se parametrizó dinámicamente el puerto con valor por defecto `27017` manteniendo retrocompatibilidad total:
  ```properties
  # Configuración corregida y flexible
  spring.data.mongodb.uri=mongodb://${MONGO_HOST:localhost}:${MONGO_PORT:27017}/palacio_db
  spring.mongodb.uri=mongodb://${MONGO_HOST:localhost}:${MONGO_PORT:27017}/palacio_db
  ```

---

### 2.2. Omisión de Variables de Seguridad en el Pipeline de CI (`ci.yml`)
* **Severidad:** Media (Riesgo de fallo en integración continua).
* **Diagnóstico:** El filtro de seguridad `RateLimitFilter.java` implementa una verificación `@PostConstruct` estricta que exige que la variable `PALACIO_PROXY_TOKEN` tenga un largo mínimo de 24 caracteres y no use secretos prohibidos por defecto. Sin embargo, en [`.github/workflows/ci.yml`](file:///C:/Users/hdari/Desktop/palacio-del-mar/.github/workflows/ci.yml#L45-L49), el trabajo de backend no exportaba `PALACIO_PROXY_TOKEN` ni `PAYMENTS_WEBHOOK_SECRET` en el bloque `env:`.
* **Solución Aplicada:** Se inyectaron explícitamente ambas variables en el paso `Run Backend Tests & Generate Coverage` del flujo de GitHub Actions para evitar fallos durante la carga de contexto de Spring.

## 4. 🛡️ Auditoría de Seguridad y Hallazgos Históricos (PDM)

Se revisó el cumplimiento de los 10 hallazgos de seguridad documentados en el historial de calidad del marketplace:

1. **Integridad de Precios (PDM-01 / PDM-02):** Todo cálculo de órdenes de comida y experiencias se cotiza autoritativamente en la base de datos MongoDB; el backend ignora cualquier precio manipulado enviado desde el cliente (`PriceIntegritySecurityTest` activo y pasando).
2. **Aislamiento Multi-anfitrión & Anti-IDOR (PDM-03):** La validación `hasAccessToBooking` y las consultas por propiedad/sucursal impiden que un anfitrión acceda a reservas ajenas.
3. **Paginación en Panel de Anfitrión (PDM-04):** El endpoint `/api/host/bookings` implementa `Page<BookingDTO>` y `subList` seguro para evitar desbordamiento de memoria por grandes volúmenes de datos.
4. **Generación de PIN SmartLock Criptográficamente Seguro (PDM-07):** Se verificó que `HostController.java` emplea `SECURE_RANDOM.nextInt(100000, 1000000)` para generar códigos de acceso al alojamiento.
5. **Prevención de Mass Assignment en Promociones (PDM-08):** La creación de promociones está restringida a través del DTO validado `PromotionRequest`, impidiendo inyecciones de campos privilegiados.
6. **Inyección CRLF en feeds iCal RFC 5545:** Sanitización activa comprobada mediante `ICalServiceAdversarialTest`.
